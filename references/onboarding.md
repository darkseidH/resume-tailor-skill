# Build a Usable Professional Profile

Read the mapped narrative sources and assemble a concise summary using [the profile summary template](../templates/profile-summary.md). Preserve all substantive roles and project provenance. Do not make the user convert notes to a rigid schema before understanding them.

If the user supplies an existing CV, map it as a secondary source for contact details, chronology, earlier roles and stated language levels. For a PDF, preserve a private source snapshot and extracted text; check the relevant pages visually when extraction splits names, dates or credentials. Distinguish extraction artifacts from genuine source conflicts. Ask about real conflicts, and prefer the user's explicit current correction over an older CV while retaining both references. Do not search unrelated documents to fill missing details.

For each role or project, capture context, dates, problem addressed, personal contribution, tools, outcome, and evidence references. Capture education and coursework separately from professional experience. Record certifications as completed, ongoing, or unknown according to the source; inventory every confirmed spoken language, whether or not a job mentions it, and record proficiency only when provided. Associate each professional project with its confirmed employer/role; retain unknown associations for clarification.

Ask one focused question at a time, choosing the uncertainty most likely to change an accurate description. Ask whether “developed an API” means the whole service or a specific team contribution. Ask about deployment when relevant rather than inferring it from development. Where metrics are absent, ask whether measurement exists; if it does not, use a qualitative factual outcome.

When dates or titles conflict, show both source excerpts and ask which is correct. Retain the unresolved versions; do not choose the more favorable one. Candidate-provided source assertions count as evidence, not third-party verification.

The baseline is usable when the main roles, projects, education and skills can be described without misleading ownership or chronology. Coverage gaps that are not material can remain unknown until a job requires them. At each completed clarification topic, follow [profile-updates.md](profile-updates.md) to propose reusable additions/corrections, obtain approval, and apply and verify approved edits. Present the summary, unresolved questions and actual profile-update status to the user. Building the skill itself never grants approval to edit candidate documents.
